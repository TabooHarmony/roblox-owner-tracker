# roblox-owner-tracker

Live purchase-count estimation for Roblox-published catalog items. Type a
catalog ID; the site walks the live all-time-sales ranking around the item and
returns an interval between the nearest pioneering neighbors with measured,
final purchase counts.

Method by **Maggy (Maggy Rarefication)** —
[original video](https://www.youtube.com/watch?v=7a-ViNgReAo).

## What it does

1. Fetch the item's identity from Roblox (`economy.roblox.com/v2/assets/<id>/details`).
2. If the creator isn't Roblox, stop (v1 covers Roblox-published items only).
3. Walk the live all-time-sales search for the item's name with rainbow-color
   padding, `includeNotForSale=true`, creator filter Locked to Roblox. This is
   the recipe the community settled on because the padding keeps same-era
   same-creator neighbors on the ranked list.
4. On the ranked list, find the nearest wiki-anchored item above the target
   that's closed-final (went off sale, has a published count observed *after*
   the close) and the same below. The interval between their counts is the
   estimate.

If only one side has evidence, you see that side and no estimate. If neither
side does, a plain "no estimate is possible." There is no confidence score,
no stale estimation, no "low trust" wiggle.

## What it never shows you

- **Anchor points copy-pasted from the wiki**: any count seen on the wiki that
  was printed while the item was still on sale is a floor, not a final — the
  site excludes those from use as bracket endpoints (the label `(final count,
  as of <date>)` shows what the anchor actually carries, always).
- **Robux value of brackets**: counts are purchases, not currency.
- **Anything for UGC/group items**. That dialog returns a one-line note.
- **Former on-sale items that came back after 2020**. Their original wiki
  counts were real when printed but the item later sold again, so they're
  re-classified out of the anchor set (see `site/rerelease_post2020.json` —
  193 items, e.g. ASCII White, Evil Duck, Lampshade). When you look one of
  those up, you get a bracket from whatever eligible neighbors exist, not
  from the item's own stale wiki number.

## Data

- `anchors/anchors_harden.jsonl` — the wiki harvest: 14,463 catalog items
  with parsed sale windows, purchase counts, and inspection fields. Source of
  truth; regenerated by hand and reviewed before being committed.
- `site/anchors_eligible.json`, `site/rerelease_post2020.json` — derived
  artifacts built by `pipeline/build_site_data.py`. To refresh:
  `python3 pipeline/build_site_data.py`.
- Wiki purchase counts were cross-checked against the leaked frms/workframes
  owner-count dump on the 100 overlapping items; all 100 agree exactly.

## Layout

    pipeline/                 the one remaining script: build_site_data.py
